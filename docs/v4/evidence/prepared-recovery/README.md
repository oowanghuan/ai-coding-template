# 已准备但未启动工作区的有限恢复

实现提交：`f31e751826ec68b0d4e6eb2868cc9ae21f8e1a04`。
本批由第三次自然续做投递接手 WP-302，沿用 OD-09，未新开模型会话。

## 修复范围

原接口要求持有实际进程句柄并确认退出，因而无法处理“工作目录已准备，但
执行器从未启动”的情况。新接口 `handoff.recover_prepared` 在同一 Store 事务内
核对启动历史、授权和最终快照，再撤销旧执行权并允许下一执行者认领。

初审发现仅凭没有 `run-begin` 记录仍不充分：外部启动器可能拥有独立的启动
许可。因此没有发布最初的纯历史判定方案。最终实现要求在认领时显式选择
`direct-local-only`，生成保留命名空间；外部客户端和独立 Driver 在配置准入及
每次启动前均拒绝该命名空间。检查覆盖工作区、祖先目录和最终输出路径，使用
大小写归一化防止 macOS 路径别名绕过。Driver 仍为独立 stdlib 模块，不导入
候选框架或凭候选布尔值判断没有外部执行权。

新路径必须同时满足：专用域的新准备记录、唯一版本化启动协议证明、没有该
工作区的历史启动意图、当前有效且未变的授权、准确绑定的最终检查点，以及
实际目录与快照一致。恢复和启动意图共用权威锁，先成功的一方阻止另一方。
原令牌不能再启动或提交，后继认领取得更高 fencing token，恢复到新 Worktree，
保留旧目录。重复 operation 返回已提交回执，不重复产生交付。

成功回执为 `execution_observed=never_launched`、`process_stop_observed=false`，
不是虚构的进程退出证明。普通/旧工作区不自动升级；已启动、结果未知、历史缺失、
晚写入、规范或授权变化均不得从此路径放行。原有 owned-Popen 停止证明
仍用于已运行任务。调用说明见 [Alpha 说明](../../../../examples/alpha/README.md)。

不是一次 95 项全量绿灯。定向复跑实际观察到恢复先赢、启动先赢两种顺序，且

持久保存；公开副本只替换机器路径，见 [原始/公开双哈希](FILE-MANIFEST.json)。

## 执行边界

这是同一操作系统所有者下的合作监督器协议，不声称抵抗恶意宿主写者。使用前
必须固定新受审控制器及 Driver，并确认没有旧外部启动能力覆盖该工作区；更新
仓库源码不会取消已运行的旧 Driver。本批只在全新隔离实验中验证，没有安装或
替换生产 Driver，没有模型推理调用、凭证复制、费用、权限变更或发布。

文件保全包括已分配文件内容、删除、未提交文件和执行位；空目录拓扑完整重建
仍不在本批范围。真实 Claude/Codex 执行、自然额度恢复、跨机器接管及完整
Lite Alpha 未验收。本有限恢复项的完成不等于整个 WP-302 或 V4 产品完成。

# Prepared recovery: bounded launch-path review

Product input: `f31e751826ec68b0d4e6eb2868cc9ae21f8e1a04`, with the separately fingerprinted non-author test file. Static source review accompanies actual A01 execution; it is not an OS proof that arbitrary processes cannot exist.

- `framework/local/runner.py::run` commits `Store.change('run-begin', ...)` before `subprocess.Popen`. A committed launch intent is retained even before PID registration; this uncertainty must reject prepared recovery.
- `framework/local/external.py::run_external` commits the same launch intent before publishing `ExternalClient.submit()`. Its constructor and run entry reject reserved direct-local workspace or output-path segments before the external launch path proceeds.
- `framework/local/launch_driver.py::Driver` validates its configuration before opening the request mailbox or evaluating a job. Configuration validation independently rejects reserved direct-local directory segments anywhere in the workspace or effective output path, using case-insensitive matching. The tests include a prepublished mailbox request; an invalid configuration must still cause zero injected spawn calls.
- `framework/local/store.py` creates the reserved namespace only for an explicit `execution_domain='direct-local-only'` claim; default/general and unknown domain values are not inferred as direct-only. The modern preparation receipt binds assignment, epoch, token, work-scope fingerprint, authorization-content fingerprint, and protocol/domain markers.
- `framework/local/handoff.py::recover_prepared_state` runs under the same authority lock as `run-begin`. It checks current final checkpoint and exact workspace contents, requires the modern unique committed preparation history, rejects every prior launch intent for that workspace, and revokes the old assignment in the same transaction. The result labels `execution_observed='never_launched'` and `process_stop_observed=false`; it does not fabricate a process exit.

The early design using only preparation history without a disjoint external-launch domain was rejected before test execution because an independently prearmed external mailbox job was not excluded. No runtime failure is claimed for that unexecuted design. The executed revision additionally constrains both updated external entry points and Driver configuration, while legacy/general workspaces fail closed.

Boundary: cooperative reviewed launchers and retained local authority history, not hostile same-account writers, old/unupdated external drivers, preexisting arbitrary launch capabilities, remote hosts, or live provider authentication. Existing owned-process stop confirmation remains a distinct path. The positive fixture restores real dirty/untracked/deleted files and executable mode into a new real Git worktree, then records one delivery with `accepted=false`; it is not model implementation or engineering acceptance.

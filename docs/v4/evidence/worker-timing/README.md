## 问题与修正

1. **旧探测覆盖新限额。** 新额度观察原来不更新已受限组的代数，旧成功回包可清掉
   后来的限制。现在每次新的已提交观察推进代数，未知的在途探测仍保留，不能盲目
   另发请求。旧回包只结清原意图，明确记录 `stale_probe_result`，不能清新限额、
   提前重试或重置尝试预算；覆盖当前代数的新探测才可能恢复可用。
2. **停机快照过时。** 原来确认进程已退出与快照指纹有效，却未校核当前工作目录。
   现在停止确认、认领及恢复前后检查实际文件、内容、执行位、目录和 HEAD；晚写入
   未入快照则保留成果并阻断，停机后重取最终快照才能接管。恢复时检测到变化，
   新目录保留为 `creating`，不能运行或提交。

## 仍未覆盖

当前为单机合作控制器边界，不是对恶意宿主同账号写者的原子文件系统保证。
接管保全已分配文件及执行位，尚未完整复制空目录拓扑；检测旧目录的变化与重建
新目录全部拓扑是不同能力。通用原生 Adapter.start、真实供应商探测与额度恢复、
正常用户首任务到工程 Gate、多机接入仍未验收。Claude 限定环境认证与 Codex
执行隔离阻塞沿用 [已有诊断](../worker-lifecycle/README.md)，本轮没有新增费用、
权限变更、真实模型调用、main 合入或发布。

本轮 `probe-result` 全部来自可信控制器的已完成响应且 `available` 是明确布尔值。
现有低层接口对缺失/非布尔值会走不可用分支并结清意图，没有实现严格类型拒绝。
真实 observer 接入前必须补响应准入；不能将未知或畸形供应商输出翻译成完成事件，
本轮没有把该尚未接入的原生输入路径计为已验证。

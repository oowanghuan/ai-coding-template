# V4 最小闭环与验收计划

版本：0.1，2026-11-26。**本文件是待实施方案，不是产品通过证明。** P0 的 12 项旧版观察与下面 12 个 V4 产品场景不是同一组测试。

## 1. 验收单位和证据

验收对象必须是完整 commit SHA + 候选合入树 + 配置/规范版本，不能只填分支名或 PR 编号。每次记录运行 ID、WP、命令 argv、环境/工具版本、起止时间、退出码、通过/失败/跳过/未测数量、预期用例清单、原始产物及 SHA256、既有失败对比和独立结论。

证据分级：`static_inspection`、`fixture_execution`、`provider_live`、`hosted_live`、`independent_acceptance`。模拟器证明协议行为，不证明供应商认证、加载规则、云端权限或计费可用。作者自测不能替代独立签认。证据真实性和信任边界见 [架构 §7](V4_ARCHITECTURE.md#7-evidence-与可执行-gate)。

所有 fixture 使用合成项目/数据、临时目录和独立 Worktree。故障注入不能作用于 Owner 的真实业务库、认证配置或其他项目。缺环境时记录 blocked/not_run 和理由，禁止用“预计通过”填 passed。

## 2. 最小可运行纵向闭环

空目录 → init Lite → 最小目标及 WP-A/WP-B → 未授权 B 拒绝 → A 获授权/认领 → 隔离目录真实执行 → Runner 捕获证据 → 独立评审准确版本 → 工程验收 → B 的依赖满足后可认领 → 执行中断 → 保全 checkpoint/未提交成果 → 另一 Worker 接管 → 重新验证 → 依据权威 revision 生成进度。

再将同一合成项目迁移到 GitHub backend，在已授权测试资源上运行云/本地竞争及 Advisor 闭环。基础真实 CLI 成功后才增加云端适配；缺云权限时保持 hosted_live 未完成。

计划中的命令接口需由 WP-101/102 确定。这里不提供尚不存在的可执行 `v4` 命令；每个场景实施时把实际调用、测试代码与输出固定到证据包。

| 场景 / 对应 WP | 实际执行方案 | 必须检验的反例 | 通过条件 / 当前状态 |

| S02 已有项目接入 / 103,501 | 含已提交、dirty、untracked、自定义入口的合成仓库；先记录指纹再 dry-run/import | 重名冲突、失败中断、回退时文件已被用户修改 | 原 Git/文件成果保留；dry-run 零写入；冲突明确。**not_run** |

| S04 双 Worker 并行 / 102,303 | 两进程/独立 Worktree 同时处理不重叠 WP，记录基线与修改集合 | 同一文件/外部资源重叠、同 WP 竞争、Worker 并发超额 | 允许正确并行，冲突只有一方拥有修改权。**not_run** |
| S05 准入阻断 / 101,102 | 组合依赖里程碑、未授权/撤销授权、风险、资源、认领、范围锁 | 仅依赖 merged 未工程验收；Ready 后授权过期；旧快照启动 | claim/start 均重检，任何不满足不启动。**not_run** |
| S06 中断与接管 / 302,303 | 执行中 kill Worker，保留 dirty/untracked/已提交成果；新 Worker 甚至另一 Provider 接管 | 未知 push/部署、旧进程仍活跃、损坏 checkpoint、旧 fencing token | 先对账和保全，再授新执行权；无资产丢失/双写/盲重试。**not_run** |
| S07 假报告拒绝 / 201 | 提交手写 passed 报告；用可信 Runner 真运行通过/失败测试对照 | 伪日志+重算哈希、错 SHA、零测试、全 skip、改测试子集、超时 | 不可信/不完整结果 blocked；真实失败拒绝；真实有效证据才通过。**not_run** |
| S08 签认后契约变化 / 203 | 对指定 SHA 签认，再修改关键接口/权限/规则；计算影响并重审 | 只改一份契约、过期签名、squash 后集成树变化 | 受影响签认 invalidated，兼容性/测试及责任方复签可追踪。**not_run** |
| S09 可复现进度 / 401（Lite 部分 102） | 固定 state revision，两次生成报表比对；核查提交/评审/合入/工程/业务分别计数 | 假 done、PR 数当完成度、Issue 标签冲突、本地旧缓存 | 同输入同结果，未知项显示 unknown，投影可重建。**not_run** |
| S10 Advisor 闭环 / 402 | 专用 Issue 真实请审、回复、核查/异议、修订、新 SHA 请复核及关闭证据 | 同评论重复拉取、未授权作者、错受审 SHA、有计划无关闭证据 | 每意见可追溯，不重复处置，不冒充 Advisor 关闭。**not_run**；本机运维接入仅部分先行验证 |
| S11 云/本地重复触发 / 202,403 | 在已批准资源上两个调度进程同 revision 竞争；注入 API 超时/网络分区/重复事件 | intent 已写未发、写入成功回执丢失、过期写者复活、并发覆盖 | 唯一认领、无覆盖；未知结果停写并对账；真实 GitHub 与 hosted 记录分列。**not_run** |
| S12 Lite 轻量与风险底线 / 103,501 | 一个低风险文案 WP 完成最小闭环，记录必填项/文件数/人工步骤；高风险 fixture 再运行 | 强制 PMO/Advisor/全部 Phase/形式化；Lite 绕过权限安全门 | 低风险只需必要字段，重治理不默认启用；高风险底线仍有效。**not_run** |

## 4. 风险增强用例

并发/幂等核心选择属性测试和小状态空间模型；权限边界选择隔离及否定权限测试；迁移选择正反向和失败恢复；关键验收逻辑选择变异测试验证测试是否真能发现错误。每项由风险评估决定，普通文案只运行相应一致性/链接检查。

故障矩阵至少覆盖：进程开始前、认领后未执行、执行中、提交前后、签认后变化、外部动作完成但 receipt 丢失、接管后旧进程恢复。每个断点明确状态、保留资产及下一步允许动作。

P0 的可复跑入口：`python3 tests/p0_audit.py --output <不存在的新目录>`。退出 0 只表示“观测与冻结基线一致”，包括正确复现退出 1 的安装故障。macOS Bash 3.2 为本次环境，其他 Bash/OS 未验收。

独立 Reviewer 应从 Draft PR 精确 SHA 获取代码、复跑审计、核查日志和关键源码，区分文件证明与作者断言。后续版本必须把自己的 evidence 指向自己的执行对象，不能复用 V3 测试当 V4 通过记录。

## 6. 放行规则

设计放行：独立评审完成、重大架构和下一批范围由 Owner 确认。Alpha 放行：适用本地场景 + 两家真实 CLI + 独立证据审查；Team Beta 另需真实 GitHub 协调及 S10/S11。Enterprise 的高风险项逐项配置/验证，不以 Profile 名称隐含通过。

未通过、未测、环境不可用、豁免分别报告；豁免须有批准范围、风险、有效期和补测条件。任何 reviewer GO 都只适用于其声明范围和 SHA，不自动授权公开发布或进入下一阶段。
